# fantasy-hoops

A personal command-line tool for analysing a **Yahoo Fantasy Basketball** league:
12-team, head-to-head, 9 categories (FG%, FT%, 3PTM, PTS, REB, AST, STL, BLK, TO),
5 adds per manager per week. Built for league `106518`, team *Cripples and Bastards*.

It answers:

| Question | Command |
|---|---|
| Who is available (all players minus the 12 rosters)? | `hoops available-players` |
| Where does my team rank in each category vs the league? | `hoops team-report` |
| Did this week's adds/drops help or hurt my matchup? | `hoops add-impact` |
| Which free agents fix my weak categories? | `hoops suggest` |
| Persist a snapshot for history | `hoops import --db hoops.db` |

> **The bundled data in `fixtures/` is fake.** Player names, stats and moves are
> generated by `scripts/gen_fixture.py`. Only the team name and league id are real.

Yahoo API access is pending, so data comes from a **JSON snapshot** (to be
produced by a local scraper on the laptop). A Yahoo OAuth2 source and a public
box-score source exist as clearly marked stubs. See [LEARNING.md](LEARNING.md)
for the architecture.

## Setup

1. Install Rust (stable) via [rustup](https://rustup.rs):
   ```sh
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   ```
   `rust-toolchain.toml` makes rustup install `rustfmt` and `clippy` automatically.
2. Build and test:
   ```sh
   cargo build
   cargo test
   ```
   No system SQLite is needed: `rusqlite`'s `bundled` feature compiles it in
   (a C compiler is required; it comes with Xcode CLT on macOS / `build-essential` on Linux).

## Usage

Run from the repo root (the default snapshot path is relative):

```sh
cargo run -- available-players                       # top 20 free agents by 9-cat z-score
cargo run -- available-players --position C --sort blk --limit 10
cargo run -- team-report                             # my team, current week
cargo run -- team-report --all                       # plus every team's rank grid
cargo run -- team-report --team "team 05" --week 1   # any team by key or name fragment
cargo run -- add-impact                              # my week's moves vs my opponent
cargo run -- suggest                                 # targets my bottom-third categories
cargo run -- suggest --cats ast,to --limit 5
cargo run -- import --db hoops.db                    # save snapshot into SQLite
cargo run -- --from-db hoops.db team-report          # analyse from SQLite instead
```

Global options: `--snapshot <file>` (or env `HOOPS_SNAPSHOT`), `--from-db <file>`,
`--week <n>`. `cargo run -- --help` / `cargo run -- <command> --help` list everything.
Install the binary with `cargo install --path crates/hoops-cli` to just type `hoops`.

## Using real data

Write a JSON file with the same shape as `fixtures/sample_snapshot.json`
(top-level `league`, `teams`, `players`, `rosters`, `transactions`,
`weekly_stats`, `matchups`; season stats are **totals**, not averages) and pass
`--snapshot path/to/file.json`. `*.db`, `/data/`, `/snapshots/` and token files
are git-ignored so real league data and credentials stay local.

## Development

```sh
cargo fmt --all                                      # format
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
python3 scripts/gen_fixture.py                       # regenerate fake fixture
```

CI (`.github/workflows/ci.yml`) runs fmt, clippy, tests and a CLI smoke test on every push/PR.

## Layout

```
Cargo.toml                 workspace root (shared deps + lints)
crates/hoops-core/         library: models, datasource, db, analysis
  migrations/0001_init.sql SQLite schema
crates/hoops-cli/          `hoops` binary (clap); tests/cli.rs runs it end to end
fixtures/                  fake sample snapshot
scripts/gen_fixture.py     fixture generator
```
